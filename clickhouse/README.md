# ClickHouse metric schema

`init/001_create_metric_fact_tables.sql` is the source of truth for the ClickHouse schema.
The initialization script creates two wide fact tables in `CLICKHOUSE_DB`:

| Table | Row grain |
|---|---|
| `fact_host_metrics` | One host snapshot at one collection timestamp |
| `fact_process_metrics` | One process snapshot at one collection timestamp |

The column names consumed from Spark intentionally match the fields returned by
`host_metrics_console.py` and `process_metrics_console.py`. `ingested_at` is generated by
ClickHouse when Spark omits it from an insert.

## Inspect the live schema

Show a concise column listing:

```bash
docker compose exec clickhouse sh -c \
  'clickhouse-client --user "$CLICKHOUSE_USER" --password "$CLICKHOUSE_PASSWORD" \
  --database "$CLICKHOUSE_DB" --query "DESCRIBE TABLE fact_host_metrics"'

docker compose exec clickhouse sh -c \
  'clickhouse-client --user "$CLICKHOUSE_USER" --password "$CLICKHOUSE_PASSWORD" \
  --database "$CLICKHOUSE_DB" --query "DESCRIBE TABLE fact_process_metrics"'
```

Show the complete DDL, including the engine, partition key, and sorting key:

```bash
docker compose exec clickhouse sh -c \
  'clickhouse-client --user "$CLICKHOUSE_USER" --password "$CLICKHOUSE_PASSWORD" \
  --database "$CLICKHOUSE_DB" --query "SHOW CREATE TABLE fact_host_metrics"'
```

Query both schemas in a form that application code can consume:

```sql
SELECT
    table,
    position,
    name,
    type,
    default_kind,
    default_expression
FROM system.columns
WHERE database = currentDatabase()
  AND table IN ('fact_host_metrics', 'fact_process_metrics')
ORDER BY table, position;
```

## Apply the schema

Initialization scripts run automatically only when ClickHouse starts with a new empty data
volume. To apply the schema to an existing local volume without deleting data, run:

```bash
docker compose exec -T clickhouse sh -c \
  'clickhouse-client --user "$CLICKHOUSE_USER" --password "$CLICKHOUSE_PASSWORD" \
  --database "$CLICKHOUSE_DB" --multiquery' \
  < clickhouse/init/001_create_metric_fact_tables.sql
```

The statements use `IF NOT EXISTS`, so applying them repeatedly is safe. They do not migrate an
already existing table whose definition differs from the file.
